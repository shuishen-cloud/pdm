# 使用方法与效果

ProjectDevelopManager（命令 `pdm`）用于在开发过程中沉淀**每次提交里的问题、难点、易错点与异常**，并提供快速查询接口。

- 笔记是**记录**（发生了什么），Issue 是**流程**（要解决什么），Doc 是**快照**（当前逻辑是什么）。
- 三者通过 commit 连接，不做额外的关系层。
- 所有数据本地存储、git 友好。

---

## 一、安装与运行

### 建议：先建虚拟环境

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev,tui]"    # dev=测试工具  tui=图形界面
```

之后统一用 `.venv/bin/python` 或先 `source .venv/bin/activate`。

### 三种运行方式

```bash
# 方式一：直接跑主入口
.venv/bin/python main.py <命令>

# 方式二：以模块运行
.venv/bin/python -m pdev.cli <命令>

# 方式三：用安装时生成的 pdm 脚本
.venv/bin/pdm <命令>

# 激活后可直接写
source .venv/bin/activate
pdm <命令>
```

查看帮助：

```bash
$ python3 main.py --help

  {note,query,show,stats}
```

## 二、记笔记：`pdm note add`

每次提交（尤其是 `feat`）之后，把这次开发中遇到的问题 / 难点 / 易错点 / 异常记下来。

### 类型

| `-k` 取值 | 含义 | 简写 |
|-----------|------|------|
| `problem` | 问题 | `p` |
| `difficulty` | 难点 | `diff` / `d` |
| `pitfall` | 易错点 | `pit` |
| `exception` | 异常 | `exc` / `e` |

### 基本用法

```bash
pdm note add <commit> -k <类型> -t "<标题>" [选项...]
```

### 常用参数

| 参数 | 说明 |
|------|------|
| `-k, --kind` | **必填**，笔记类型 |
| `-t, --title` | **必填**，一句话摘要 |
| `-d, --detail` | 详细描述 |
| `-F, --file` | 涉及文件，可重复 |
| `-T, --tag` | 标签，可重复 |
| `-p, --priority` | 严重程度：`low` / `medium` / `high` / `critical` |
| `--status` | 笔记状态：`open` / `resolved` / `noted`（默认 `noted`） |
| `-i, --issue` | 升级成的 Issue ID |
| `-r, --resolve` | 该笔记解决了哪个 Issue，可重复 |
| `-a, --author` | 作者：`lwy` 自动补成 `human:lwy`，`ai:claude` 保持原样 |
| `--no-time` | 不记录当前时间 |

### 效果

```bash
$ pdm note add abc123 -k pitfall -t "token 刷新有竞态" \
      -d "并发刷新会写出旧 token" -F src/auth/token.py -T auth -p high
已记录：· [PITFALL   ] token 刷新有竞态
    commit=abc123  src/auth/token.py  #auth  sev=high
```

```bash
$ pdm note add abc123 -k difficulty -t "异步上下文拿不到 config" \
      -F src/auth/token.py -T async -a ai:claude
已记录：· [DIFFICULTY] 异步上下文拿不到 config
    commit=abc123  src/auth/token.py  #async
```

```bash
$ pdm note add def456 -k exception -t "Redis 偶发超时" \
      -F src/cache/redis.py -T cache -i 0001 -p medium
已记录：· [EXCEPTION ] Redis 偶发超时
    commit=def456  src/cache/redis.py  #cache  issue=0001  sev=medium
```

**输出行首的状态标记：**

| 标记 | 状态 | 含义 |
|------|------|------|
| `·` | `noted` | 只是记一笔，无需解决 |
| `○` | `open` | 未解决 |
| `●` | `resolved` | 已解决 |

**输出颜色**（终端下）：`problem` 红、`exception` 黄、`pitfall` 紫、`difficulty` 青。非终端或 `--json` 时自动关闭。

## 三、查看提交笔记：`pdm show`

一条命令看这次提交都记了什么。

```bash
$ pdm show abc123
· [PITFALL   ] token 刷新有竞态
    commit=abc123  src/auth/token.py  #auth  sev=high

· [DIFFICULTY] 异步上下文拿不到 config
    commit=abc123  src/auth/token.py  #async
```

提交不存在时返回退出码 1：

```bash
$ pdm show nope
commit nope 没有笔记
```

## 四、查询：`pdm query`

单条件与组合条件都由同一条命令表达。

| 参数 | 说明 | 示例 |
|------|------|------|
| `-k, --kind` | 按类型 | `-k pitfall` |
| `-s, --status` | 按状态 | `-s open` |
| `-f, --file` | 按文件，支持 **glob** | `-f 'src/auth/**'` |
| `-T, --tag` | 按标签 | `-T auth` |
| `-x, --text` | 全文搜索（标题/详情/标签） | `-x 竞态` |
| `-C, --commit` | 按提交 | `-C abc123` |
| `-i, --issue` | 按关联 Issue（升级 + 解决都算） | `-i 0001` |
| `-a, --author` | 按作者种类 | `-a ai` |
| `-n, --limit` | 最多返回条数 | `-n 10` |
| `--json` | JSON 输出 | `--json` |

### 按类型 + 文件（glob）

```bash
$ pdm query -k pitfall -f 'src/auth/**'
· [PITFALL   ] token 刷新有竞态
    commit=abc123  src/auth/token.py  #auth  sev=high

共 1 条
```

### 全文搜索

```bash
$ pdm query -x 竞态
· [PITFALL   ] token 刷新有竞态
    commit=abc123  src/auth/token.py  #auth  sev=high

共 1 条
```

### 找出 AI 撰写 / AI 参与的笔记

```bash
$ pdm query -a ai
· [DIFFICULTY] 异步上下文拿不到 config
    commit=abc123  src/auth/token.py  #async

共 1 条
```

### 按 Issue 反查

```bash
$ pdm query -i 0001
· [EXCEPTION ] Redis 偶发超时
    commit=def456  src/cache/redis.py  #cache  issue=0001  sev=medium

共 1 条
```

### 组合条件

```bash
$ pdm query -s open -n 2
○ [PROBLEM   ] 登录接口超时
    commit=def456  src/auth/login.py  #auth

共 1 条
```

### JSON 输出（供脚本 / TUI 消费）

```bash
$ pdm query -k pitfall --json
[
  {
    "commit": "abc123",
    "kind": "pitfall",
    "title": "token 刷新有竞态",
    "detail": "并发刷新会写出旧 token",
    "author": "human:alice",
    "files": ["src/auth/token.py"],
    "severity": "high",
    "status": "noted",
    "issue_id": null,
    "resolves": [],
    "tags": ["auth"],
    "created_at": "2026-10-12T12:34:15.795904+00:00"
  }
]
```

### 结果排序

按 `created_at` **降序**（新 → 旧）；未记录时间的笔记排在最后。

### 别名

`pdm note list` 与 `pdm query` 完全等价。

## 六、配置

配置来源优先级（高 → 低）：

```
CLI 参数  >  PDM_* 环境变量  >  项目 .pdm.json  >  ~/.config/pdm/config.json  >  默认值
```

### 项目配置 `.pdm.json`

放在项目根目录（会从当前目录向上查找）：

```json
{
  "store": "notes",
  "default_author": "human:alice",
  "color": true,
  "note": {
    "default_status": "open",
    "require_detail": false
  },
  "query": {
    "default_limit": 20
  },
  "git": {
    "repo": ".",
    "auto_commit": false
  },
  "issue": { "store": "issues" },
  "doc": { "dir": "docs" }
}
```

### 用户配置 `~/.config/pdm/config.json`

个人偏好，不随项目走（例如 `{"color": false}`）。

### 环境变量

| 环境变量 | 配置项 |
|----------|--------|
| `PDM_STORE` | `store` |
| `PDM_AUTHOR` | `default_author` |
| `PDM_EDITOR` | `editor` |
| `PDM_NO_COLOR` | `color = false` |
| `PDM_JSON` | `json_output = true` |
| `PDM_GIT_REPO` | `git.repo` |
| `PDM_GIT_AUTO_COMMIT` | `git.auto_commit` |
| `PDM_ISSUE_STORE` | `issue.store` |
| `PDM_DOC_DIR` | `doc.dir` |
| `PDM_QUERY_DEFAULT_LIMIT` | `query.default_limit` |
| `PDM_GITHUB_REPO` / `PDM_GITHUB_TOKEN` | `github.repo` / `github.token` |

**示例：环境变量覆盖项目配置**

```bash
$ PDM_STORE=/tmp/env-notes pdm note add d1 -k exception -t "写入 env 存储"
已记录：· [EXCEPTION ] 写入 env 存储
    commit=d1
```

### `--store` 的位置

写在子命令前后都可以：

```bash
pdm --store /tmp/a query -k pitfall      # 可以
pdm query -k pitfall --store /tmp/a      # 也可以
```

`--no-color` / `--json` 是**顶层选项**，需写在子命令之前。

## 七、存储布局与数据

```
.pdm/notes/
├── by-commit/
│   ├── abc123.json        # 一个 commit 一个文件，含该 commit 全部笔记
│   └── def456.json
└── index.json             # 派生索引缓存，可随时重建
```

> 开发过程数据（笔记 / feat / 设计文档）统一放在项目根的 `.pdm/`，
> 默认**不跟踪、不随代码分发**；路径均可在 `.pdm.json` 配置。

`by-commit/abc123.json`：

```json
{
  "commit": "abc123",
  "notes": [
    {
      "commit": "abc123",
      "kind": "pitfall",
      "title": "token 刷新有竞态",
      "detail": "并发刷新会写出旧 token",
      "author": "human:alice",
      "files": ["src/auth/token.py"],
      "severity": "high",
      "status": "noted",
      "issue_id": null,
      "resolves": [],
      "tags": ["auth"],
      "created_at": "2026-10-12T12:34:15.795904+00:00"
    }
  ]
}
```

`index.json`（缓存，删掉不影响数据）：

```json
{
  "count": 4,
  "by_kind": { "pitfall": 1, "difficulty": 1, "exception": 1, "problem": 1 },
  "by_status": { "noted": 3, "open": 1 },
  "by_issue": { "0001": 1 },
  "commits": ["abc123", "def456"]
}
```

**设计取舍：**

- **一 commit 一文件** —— 写入原子、commit 即索引键、与 `git log` 对齐。
- 损坏的 JSON 文件会被跳过，不影响其余数据。
- 索引是派生的，可在代码中调用 `NoteStore.rebuild_index()` 重建。

## 八、与 Issue / 文档的衔接

笔记不替代 Issue 流程。二者的连接靠两个字段：

```
CommitNote.issue_id   →  升级成的 Issue
CommitNote.resolves   →  解决了哪些 Issue
```

**流程示例：**

```bash
# 1. feat 提交，发现一个一时修不了的坑
$ pdm note add abc123 -k pitfall -t "token 刷新有竞态" --status open
已记录：○ [PITFALL   ] token 刷新有竞态
    commit=abc123

# 2. 升级为 Issue（在 pdev 代码里新建 Issue 后回填）
#    note.issue_id = "0001"

# 3. 修好后提交，记录"解决了什么"
$ pdm note add def456 -k problem -t "加锁修复 token 竞态" -r 0001 --status resolved
已记录：● [PROBLEM   ] 加锁修复 token 竞态
    commit=def456

# 4. 反查该 Issue 的所有相关笔记（升级 + 解决）
$ pdm query -i 0001
```

**风险项** 就是"记了 open 的坑但既没解决、也没升级为 Issue"——`pdm stats` 里的 `risky` 计数，用来防止笔记被遗忘。

## 九、快速上手

```bash
# 1. 建虚拟环境（第一次）
python3 -m venv .venv
.venv/bin/pip install -e ".[dev,tui]"

# 2. 在项目里生成配置（可选）
cat > .pdm.json <<'EOF'
{ "default_author": "human:你" }
EOF

# 3. 提交代码后，记下这次踩的坑
.venv/bin/pdm note add $(git rev-parse --short HEAD) \
    -k pitfall -t "简要描述" -F 相关文件.py -T 模块

# 4. 随时查询
.venv/bin/pdm query -k pitfall -f 'src/auth/**'   # 这个模块有哪些坑
.venv/bin/pdm query -x 关键词                      # 全文找
.venv/bin/pdm query -a ai                          # AI 参与的记录
.venv/bin/pdm show $(git rev-parse --short HEAD)   # 这次提交都记了什么
.venv/bin/pdm stats                                # 总览 + 风险项
```
