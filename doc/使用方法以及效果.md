# 使用说明（全流程）

ProjectDevelopManager（命令 `pdm`）是一套**开发过程管理器**：把一次功能开发
从设计到收尾的全流程记下来，并强制「先设计、再测试、后实现、要审查」。

四个概念，一条主线：

| 概念 | 是什么 | 类比 |
|------|--------|------|
| **Feat** | 一次功能开发的索引卡（设计规格 + 阶段游标 + 审查勾选） | 工单 |
| **Note** | 挂在某个 commit 上的开发笔记（坑/难点/异常） | 便签 |
| **Doc** | 设计正文（外置 Markdown，`doc/feat/<slug>.md`） | 设计稿 |
| **Issue** | 需要跟踪的缺陷/任务 | 缺陷单 |

四者通过 **commit** 连接，不额外建关系层；数据全在本地、git 友好。

---

## 一、安装与运行

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev,tui]"    # dev=测试工具  tui=图形界面

# 三种入口（等价）
.venv/bin/pdm <命令>
.venv/bin/python -m pdev.cli <命令>
.venv/bin/python main.py <命令>
```

顶层命令一览：

```bash
$ pdm --help
usage: pdm [-h] [--store STORE] [--json] [--no-color]
           {note,query,show,verify,feat,review,theme,ui,stats} ...

    note     笔记操作
    query    组合查询
    show     查看某提交的全部笔记
    verify   验证方法与执行
    feat     功能开发记录（设计→测试→实现）
    review   项目代码掌握程度与告警
    theme    查看 / 设置 TUI 主题
    ui       图形界面（TUI，仿 lazygit）
    stats    汇总统计
```

全局选项：`--store DIR`（存储目录）、`--json`（机器可读）、`--no-color`。
`--json` 和 `--no-color` 写在**子命令之前**效果最稳。

## 二、五分钟上手

一条 Feat 的完整生命周期：

```bash
# 1. 新建：登记设计规格（五项必填，见下节）
pdm feat new token-cache \
    --title "token 缓存层" \
    --doc feat/token-cache.md \
    --api "TokenCache.get(key) -> Optional[str]" \
    --log "缓存未命中时记录 key 与回源耗时" \
    --fallback "Redis 不可用降级为直连 DB，记 warning" \
    --design-note "热点 key 读多写少，加一层内存缓存即可，不引入新依赖" \
    --impl-note "LRU dict + TTL 时间戳，后台线程惰性清理" \
    --data-model "TokenCache._store: dict[str, tuple[str, float]] —— key→(值, 过期时刻)" \
    --sample '{"tok-1": ("abc", 1730000000.0)}' \
    --change "pdev/cache.py::TokenCache —— 新增类" \
    --change "pdev/config.py::CacheConfig.ttl —— 新增字段"

# 2. doc 阶段：写设计正文，提交
pdm feat commit doc token-cache -m "定 TTL 语义与降级路径" \
    --files doc/feat/token-cache.md

# 3. test 阶段：写测试并提交
pdm feat commit test token-cache -m "先钉未命中与过期两条路径" \
    --files tests/test_cache.py

# 4. feat 阶段：实现并提交
pdm feat commit feat token-cache -m "落 LRU + TTL，降级走直连" \
    --files pdev/cache.py

# 5. fix 阶段：修问题 / 回填
pdm feat commit fix token-cache -m "过期判定在多线程下偶发误命中" \
    --files pdev/cache.py

# 6. 审查：逐项勾选 + 写评论
pdm feat review token-cache --item api:0 --review --by human:lwy
pdm feat review token-cache --item api:0 --test --cmd "pytest tests/test_cache.py"
pdm feat comment token-cache --on api:0 -m "签名保持最小，不做泛化"

# 7. 收尾：补设计文档收尾小节，关闭
pdm feat commit close token-cache -m "收尾：记下多线程竞态与取舍" \
    --files doc/feat/token-cache.md --close

# 8. 自校验
pdm feat check token-cache
```

看进度：

```bash
pdm feat list          # 全部 feat
pdm feat show token-cache --doc --notes --verify   # 详情（含勾选与评论）
pdm review             # 全项目掌握程度
```

## 三、Feat 全流程

### 3.1 `pdm feat new` —— 五项必填

```
./run.sh --help            # 或 .venv/bin/pdm --help
```

| 参数 | 必填 | 含义 |
|------|:----:|------|
| `<slug>` | ✅ | 唯一标识，小写字母/数字/连字符 |
| `-t/--title` | ✅ | 一句话标题 |
| `--doc` | ✅ | 设计正文路径（约定 `feat/<slug>.md`） |
| `--api` | ✅ | 代码接口签名（可多次） |
| `--log` | ✅ | 会打什么日志（可多次） |
| `--fallback` | ✅ | 异常兜底（可多次） |
| `--design-note` | ✅ | **设计思路**：为什么这么做 |
| `--impl-note` | ✅ | **实现方式**：怎么落地的 |
| `--data-model` | ✅ | **核心数据结构**（可多次） |
| `--sample` | ✅ | **样例数据**：结构的真实实例（可多次） |
| `--change` | ✅ | **对既有代码的改动**（可多次） |

五项设计字段**缺一即拒**（退出码 2）：

```bash
$ pdm feat new a -t A --api "f()"
错误：缺必填字段：设计思路、实现方式、核心数据结构、样例数据、对既有代码的改动
```

写不出内容时**也要写明「无」**，例如 `--sample "无：纯计算，无外部数据"`。

几条约定：

- `--design-note` / `--impl-note` 是**整段文本**（可含换行）；
- `--data-model` 写**类型/结构**：`Cache: dict[str,int] —— key→计数`；
- `--sample` 写**该结构的实例**（不是命令行用法）：`{"a": 1}`；
- `--change` 定位到**符号**：`pdev/feat.py::Feat.set_comment —— 新增方法`
  （`check` 会警告"没定位到符号"的写法）。

### 3.2 五阶段提交 `pdm feat commit`

阶段流水线**单向**，`pdm feat commit` 会在**提交前**拒绝乱序：

```
doc → test → feat → fix → close
```

| 阶段 | 生成前缀 | 什么时候用 |
|------|---------|-----------|
| `doc` | `doc(<slug>):` | 先写设计正文 |
| `test` | `test(<slug>):` | 按设计写测试 |
| `feat` | `feat(<slug>):` | 实现 |
| `fix` | `fix(<slug>):` | 修 Bug / 回填异常 |
| `close` | `doc(<slug>):` | 收尾文档（`--close` 同时置 closed） |

```bash
pdm feat commit feat token-cache -m "落 LRU + TTL" \
    --body "一句话评价这次提交" \
    --files pdev/cache.py --files tests/test_cache.py

# --files 可多次；新文件自动 git add
# --dry-run 预演；--no-verify 跳过钩子
```

允许停留在当前阶段重复提交（如连续两次 `fix`）；禁止回退。

> **纪律**：不要手敲 `git commit`——绕过阶段校验，`pdm feat check` 事后才报。

### 3.3 其余 feat 子命令

| 命令 | 作用 |
|------|------|
| `pdm feat list [--status S] [--kind K] [--open]` | 列出 feat |
| `pdm feat show <slug> [--doc] [--notes] [--verify] [--debug]` | 查看详情 |
| `pdm feat set <slug> <status>` | 手动推进状态（`draft→testing→integrated→fixing→closed`，单向） |
| `pdm feat link <slug> <commit>` | 手动串联 commit（一般由 `feat commit` 自动做） |
| `pdm feat unlink <slug> <commit>` | 解除 commit 关联 |
| `pdm feat found <slug> <text>` | 记录 fix 阶段发现的异常 |

```bash
pdm feat list --open
pdm feat set token-cache fixing
pdm feat found token-cache "并发下过期判定偶发误命中"
```

### 3.4 `pdm feat check` —— 自约束校验

```bash
pdm feat check token-cache     # 单条
pdm feat check                 # 全仓（含孤儿 commit）
pdm feat check --strict        # warning 也算失败（退出码 1）
pdm feat check --json
```

规则（`code` → level）：

| code | level | 含义 |
|------|-------|------|
| `empty-doc` / `no-api` / `no-fallback` | warning | 字段缺失 |
| `draft-has-commit` | warning | draft 却已串 commit |
| `closed-no-commit` | error | closed 却没串 commit |
| `commit-conflict` | error | 同一 commit 被多个 feat 认领 |
| `commit-missing` | error | commit 在 git 中不存在 |
| `orphan-commit` | warning | git 里有 commit 未被任何 feat 认领 |
| `stage-prefix` / `stage-order` / `missing-stage` | warning | 阶段前缀/顺序/缺失问题 |
| `note-no-verify` / `commit-no-note` | warning | 笔记/验证覆盖缺口 |
| `review-none` / `review-low` | warning | 未审查 / 审查覆盖率过低 |
| `missing-fields` | warning | 缺五项必填（仅对 `feat-fields` 后新建的 feat） |
| `vague-change` / `empty-sample` | warning | 改动没定位到符号 / 样例敷衍 |

退出码：有 error → 1；`--strict` 时 warning 也 → 1。

## 四、审查与掌握程度

给每条 Feat 的**可审项**加两个独立勾选位，并支持逐条评论。

### 4.1 可审项与 key

可审项由 Feat 的列表字段展开，key 形如：

| 字段 | key |
|------|-----|
| 设计文档 | `doc` |
| 交付接口 | `api:0` / `api:1` … |
| 会打的日志 | `logs:0` … |
| 异常兜底 | `fallbacks:0` … |
| 核心数据结构 | `data_model:0` … |
| 样例数据 | `samples:0` … |
| 对既有代码的改动 | `changes:0` … |

### 4.2 勾选：`pdm feat review`

```bash
# 列出某 feat 的可审项与状态
pdm feat review token-cache
# token-cache  审查 0/7  测试 0/7
# [ ][ ] doc          feat/token-cache.md
# [ ][ ] api:0        TokenCache.get(key) -> Optional[str]
# ...

# 勾单项（[审]）
pdm feat review token-cache --item api:0 --review --by human:lwy
# 勾 [测]（登记实际执行的命令与结果）
pdm feat review token-cache --item api:0 --test --cmd "pytest tests/test_cache.py" --status passed

# 批量：整条 feat / 某一片
pdm feat review token-cache --all --review
pdm feat review token-cache --item api --review      # 所有 api:*
pdm feat review token-cache --item fallbacks --untest

# 取消
pdm feat review token-cache --item api:0 --unreview
pdm feat review token-cache --item api:0 --untest
```

- `[审]` 与 `[测]` **独立**：可以只审不测。
- `--all` 与 `--item` **互斥**；一次动作只写一次盘。
- 单条命中沿用单条输出；批量则逐行列出后给汇总。
- `--test` 未给 `--cmd` 会提示（不阻断）。

### 4.3 评论：`pdm feat comment`

对某个条目写人话解释（可留空、可多行）：

```bash
pdm feat comment token-cache --on api:0 -m "签名保持最小，不做泛化"
pdm feat comment token-cache --on api:0          # 查看该条
pdm feat comment token-cache --on api:0 --clear  # 清除
pdm feat comment token-cache                     # 列出全部已写评论
```

评论与勾选**独立**，共用同一套 key；空评论不落盘。

### 4.4 阶段审核：`pdm feat stage-review`

除了逐条审查，还可以对**整个阶段**签一个「人工审核通过」。进入下一阶段前
要求**上一阶段已审**（默认只告警，配置可升级为硬阻断）。

```bash
pdm feat stage-review token-cache doc --by human:lwy   # 审过 doc 阶段
pdm feat stage-review token-cache --list                # 看各阶段状态
pdm feat stage-review token-cache doc --clear           # 撤销
```

```
  ✓ doc    human:lwy  2026-10-14 11:49:48
  · test   （未审）
```

- 审核人必须是 `human:<名字>`（默认 `require_human=true`，防 AI 自审）。
- 开 `stage_review.enabled=true` 后，上一阶段未审则 `pdm feat commit` **拒绝**：
  ```
  错误：上一阶段 [doc] 尚未人工审核；先跑：pdm feat stage-review <slug> doc --by <human:名字>
  ```
- 默认只由 `pdm feat check` 报 `stage-unreviewed`（warning）。

### 4.5 掌握程度：`pdm review`

```bash
$ pdm review
掌握程度：poor  0.00 / 1.00
  可审项    7（来自 1 条 feat）
  人工审查  0  0%
  测试通过  0  0%
  告警
    ! [no-review] 完全不审查：7 个可审项无一项被人工确认
    ! [low-review] 人工审核覆盖率过低：0%（低于 60%）
    ! [untested] 完全没有测试通过记录
```

- `score = 0.6 × 人工审核覆盖率 + 0.4 × 测试覆盖率`，分档
  `none / poor / fair / good / excellent`。
- **有告警时退出码 1**（可当 CI 门禁）。
- 阈值 `review.min_coverage`（默认 `0.6`）。

列出**待办清单**（跨全仓，查询性质，退出码恒为 0）：

```bash
pdm review --unreviewed            # 哪些还没人工审查
pdm review --untested              # 哪些还没测试通过
pdm review --unreviewed --untested # 既未审且未测（交集）
pdm review --unreviewed --json
```

### 4.6 查看：`pdm feat show`

```bash
pdm feat show token-cache                    # 规格 + [审][测] 标记 + 💬 评论
pdm feat show token-cache --doc              # 附设计正文
pdm feat show token-cache --notes --verify   # 附关联笔记与验证
pdm feat show token-cache --debug            # 附原始 JSON 与路径
pdm --json feat show token-cache             # 完整字段
```

输出示例：

```
交付接口
  [x][ ] · TokenCache.get(key) -> Optional[str]
    💬 签名保持最小，不做泛化
  [ ][ ] · TokenCache.put(key, val, ttl) -> None
```

## 五、笔记：`pdm note add`

每次提交后，把这次踩的坑/难点/异常记下来，并登记可复现的验证方法。

```bash
pdm note add <commit> -k pitfall -t "token 刷新有竞态" \
    -d "并发刷新会写出旧 token" \
    -F src/auth/token.py -T auth -p high \
    --verify 'test=tests/test_token.py::test_refresh;method=200 并发断言只刷新一次;expected=passed'
```

| 参数 | 说明 |
|------|------|
| `-k/--kind` | `problem`/`difficulty`/`pitfall`/`controlled-exception`/`bug` |
| `-t/--title` | 一句话摘要（必填） |
| `-d/--detail` | 详细描述 |
| `-F/--file` | 涉及文件（可多次） |
| `-c/--catches` | 可控异常捕获的类型（配 `controlled-exception`） |
| `--verify` | 验证方法：`test=<用例>` / `cmd=<命令>` / `manual=<步骤>`；可加 `;method=;expected=` |
| `-T/--tag` | 标签（可多次） |
| `-p/--priority` | `low`/`medium`/`high`/`critical` |
| `--status` | `open`/`resolved`/`noted` |
| `-i/--issue` | 升级成的 Issue ID |
| `-r/--resolve` | 解决了哪个 Issue（可多次） |
| `-a/--author` | `lwy` → `human:lwy`；`ai:claude` 保持原样 |

**类型语义**：`problem`/`difficulty`/`pitfall` 是**资产**（沉淀知识）；
`bug` 是**负债**（必须修）；`controlled-exception` 是**已捕获的异常**（资产）。

## 六、查询与查看

### `pdm show <commit>`

看某次提交的全部笔记（含提交标题/作者/时间）。

### `pdm query`（等价 `pdm note list`）

```bash
pdm query -k pitfall -f 'pdev/**'      # 这个模块有哪些坑
pdm query -x 竞态                       # 全文搜索
pdm query -a ai                         # AI 撰写/参与的笔记
pdm query -i 0001                       # 关联某 Issue
pdm query -k bug -s open -p high        # 未修的严重缺陷
pdm query --json                        # 机器可读
```

| 参数 | 说明 |
|------|------|
| `-k/--kind` | 按类型 |
| `-s/--status` | 按状态 |
| `-f/--file` | 按文件（支持 glob） |
| `-T/--tag` | 按标签 |
| `-x/--text` | 全文搜索 |
| `-C/--commit` | 按提交 |
| `-i/--issue` | 按关联 Issue |
| `-a/--author` | 按作者种类（`human` / `ai`） |
| `-n/--limit` | 最多条数 |

## 七、验证：`pdm verify`

| 命令 | 作用 |
|------|------|
| `pdm verify list` | 列出全部验证条目（`--status` / `--unverified` 筛选） |
| `pdm verify show <commit>` | 展开笔记 + 验证详情 + 关联测试脚本源码 |
| `pdm verify run [commit]` | 执行验证并回写结果（`last_status`） |

```bash

pdm verify run --status failed       # 只重跑上次失败的
pdm verify run -n                    # dry-run：只打印将执行的命令
```

## 九、配置

配置优先级（高 → 低）：

```
CLI 参数 > PDM_* 环境变量 > 项目 .pdm.json > 用户 ~/.config/pdm/config.json > 内置默认
```

常用项（详见 `doc/配置文件说明.md`）：

```json
{
  "store": ".pdm/notes",
  "default_author": "human:lwy",
  "feat": { "store": ".pdm/feats" },
  "doc": { "dir": "doc" },
  "review": { "min_coverage": 0.6, "warn_no_review": true, "warn_untested": true },
  "stage_review": { "enabled": false, "require_human": true }
}
```

- `doc.dir` 是设计文档根目录（默认 `doc`，即 `doc/feat/<slug>.md`，
  随代码进 git）。
- `review.min_coverage` 是 `low-review` / `review-low` 的阈值。
- `stage_review.enabled` 为真时，阶段审核未过则 `feat commit` 直接拒绝；
  `require_human` 限定审核人必须是 `human:` 前缀。

## 十、存储布局

```
.pdm/
├── notes/            笔记（可进 git）
│   ├── by-commit/    提交 hash 分桶
│   └── ...
└── feats/
    └── by-id/<slug>.json   一条 feat 一个文件
doc/feat/<slug>.md    设计正文（随代码进 git）
```

`Feat` 的 JSON 关键字段：

```json
{
  "slug": "token-cache",
  "title": "token 缓存层",
  "status": "closed",
  "stage": "close",
  "doc": "feat/token-cache.md",
  "api": ["..."], "logs": ["..."], "fallbacks": ["..."],
  "design_note": "...", "impl_note": "...",
  "data_model": ["..."], "samples": ["..."], "changes": ["..."],
  "reviews": { "api:0": { "reviewed": true, "reviewed_by": "human:lwy",
                          "tested": true, "test_command": "pytest ...",
                          "test_status": "passed" } },
  "comments": { "api:0": "签名保持最小，不做泛化" },
  "commits": ["..."], "notes": ["..."], "discovered": ["..."]
}
```

- `reviews` / `comments` **只记录被操作过的项**（未操作不落盘）。
- 规格项删除后，旧记录成为**孤儿**：保留在 JSON，但不计入统计。

## 十一、常见问题与反模式

| 问题 | 说明 |
|------|------|
| 手敲 `git commit` | ❌ 绕过阶段校验；一律用 `pdm feat commit` |
| `feat new` 报缺必填 | 五项设计字段必填；没有就写「无：原因」 |
| `--json` 输出里混了人话 | `--json` 只出 JSON；放子命令前最稳 |
| 批量勾选只生效一条 | `--item` 一次一项；要多条用 `--all` 或 `--item <前缀>` |
| `pdm review` 退出码 1 | 有告警（正常用于门禁）；只是查看用 `--unreviewed` |
| `feat check` 报 `orphan-commit` | git 里有 commit 未被任何 feat 认领（历史遗留常见） |
| 设计文档读不到 | 确认 `doc.dir` 与 `feat.doc` 拼出的路径存在 |

**不要做**：

- 写完代码才补设计文档（`doc` 必须在 `feat` 之前）；
- 把 test/fix 塞进一次提交（`missing-stage` 会报）；
- 提交信息前缀用 `doc|test|feat|fix` 之外的词（中性前缀
  `refactor|init|chore` 例外）。
