# 使用说明全流程重写（docs-rewrite）

> 先于实现编写。现有 `doc/使用方法以及效果.md` 停在「笔记 + 查询 + 统计」，
> 完全没有 Feat 全流程与审查机制。本 feat 按**真实命令行为**重写使用说明，
> 并补齐 `doc/配置文件说明.md` 的 `review` 段。

## 问题

主文档（546 行）写于 Feat 审查机制之前，缺三类内容：

1. **Feat 全流程**：`new`（五项必填）→ `commit`（五阶段）→ `close` 一字未提；
2. **审查机制**：`[审][测]` 勾选、条目级评论、批量勾选、`pdm review`、
   `--unreviewed/--untested` 待办清单，全无；
3. **命令面已漂移**：`feat` 子命令从 6 个涨到 11 个，顶层多了 `review`。

配置文件说明缺 `review` 段；`feat.view` 之外的字段未见核对。

根因：文档随功能增长失同步——功能在推进，文档没跟上。

## 规范

### 重写范围

| 文件 | 动作 |
|------|------|
| `doc/使用方法以及效果.md` | **重写**为「全流程使用说明」 |
| `doc/配置文件说明.md` | 补 `review` 段；核对各段与代码一致 |
| `doc/DATA_MODEL.md` | 核对新增字段（`reviews`/`comments`/五项设计字段） |
| `doc/TUI使用说明.md` | 不动（TUI 暂不开发） |

### 主文档结构（重写后）

按"从装到用"的真实顺序：

1. **安装与运行**（保留，核对）
2. **五分钟上手**：建 feat → 填五栏 → 走五阶段 → 勾审查 → 收尾
3. **Feat 全流程**（新增，重点）
   - `feat new` 五项必填的语义与例子
   - `doc → test → feat → fix → close` 阶段提交
   - `check` 的全部规则与退出码
4. **审查与掌握程度**（新增，重点）
   - `[审][测]` 两bit、条目 key 规则
   - `feat review --item/--all/前缀`
   - `feat comment`（条目级评论）
   - `pdm review`、`--unreviewed/--untested`
   - `feat show` 的标记与评论展示
5. **笔记**（保留：note add）
6. **查询与查看**（保留：query / show）
7. **验证**（保留：verify list/show/run）
8. **统计**（更新：加掌握程度）
9. **配置**（指向配置文件说明）
10. **存储布局**（更新：加 reviews/comments）
11. **常见问题 / 反模式**（新增：如 `--json` 只出 JSON、批量与单条的区别）

### 准确性要求

- 每条命令的参数、输出、退出码**以实际运行为准**（先跑再写）。
- 阶段顺序、必填字段、告警码等**与代码常量对齐**（`stage.py` / `check.py`）。
- 所有示例命令必须能跑通（用临时项目验证）。

## 接口

- 纯文档改动，**无代码接口**。
- 允许附带：修正文档中发现的**与代码不符**的描述（不改代码）。

## 日志

- 不适用（文档）。

## 兜底

- **命令行为不确定**：跑一遍再写，不臆测。
