# 发布与改名计划（现状快照 + 分步路线）

> 记录时间：2026-10-16，分支 `feat/web-ui`
> 性质：**计划文档，非设计文档**。记录"要做什么、为什么、先做什么、暂缓什么"。
> 落地时按本项目流程另开 feat（`doc → test → script → feat → fix → close`）。

---

## 0. 背景：为什么必须处理命名

本项目命令行现叫 **`pdm`**，与 PyPI 上的知名包 **PDM**（Python 包/依赖管理器，
`pdm-project/pdm`，文档站 pdm-project.org）**同名**。

实测核实：

| 名称 | PyPI 状态 | 说明 |
|------|-----------|------|
| `pdm` | **已占用** | 官方 PDM，本项目无法注册同名包 |
| `pdev` | 已被占用 | 不可用作包名 |
| `dev-ledger` | **可用**（404） | 候选包名 |
| `dl`（命令） | 无 PyPI 概念 | 命令名，与官方 `pdm` 不冲突 |

**结论**：若要发布到 PyPI，包名与命令名都必须避开 `pdm`。

### 三个名字是独立的

| 维度 | 是否冲突 | 处理 |
|------|---------|------|
| PyPI 包名（`pip install X`） | ❌ 必须改 | `pdm` 已占，改用 `dev-ledger` |
| 命令名（敲的 `pdm xxx`） | ⚠️ 需改 | 与官方 PDM 互相覆盖，改用 `dl` |
| GitHub 仓库名 | ✅ 无所谓 | `owner/repo` 天然唯一 |

---

## 1. 决定

1. **新命令名：`dl`**（短、易敲、不撞）。
2. **PyPI 包名：`dev-ledger`**（已确认可用），与内部 `Ledger` 门面语义一致。
3. **缓慢迁移，不一次性替换**：先加别名保兼容，再逐步把"现行入口文档"
   迁到 `dl`；**历史设计快照 `doc/feat/*.md` 不改**。
4. **本 branch 先验证 `Ledger` 接入 → 合并主分支 → 推远端**，让其他设备
   可读可改；发布改名随后分批进行。

### 为什么不一次性全局替换

- 全项目 `pdm` 出现约 **420 处**，其中约 **370 处在文档**，机械替换风险低但
  工作量大、易漏。
- 按本项目自身立场「**文档是快照，不追溯篡改**」：`doc/feat/*.md` 是当时的
  设计快照，回看历史时写 `pdm` 是**正确的**；改了反而破坏追溯性。
- 因此只迁"现行入口"（README、skill、usage、配置说明），历史快照保留。

---

## 2. 修改范围清点（实测）

命令式出现（`pdm ` + 子命令）统计：

| 类别 | 文件数 | 约计次数 | 是否必须改 |
|------|-------|---------|-----------|
| 内核代码 `pdev/` | ~8 | ~25 | 否（均为提示语示例文本，逻辑不依赖命令名） |
| 测试 `tests/` | ~5 | ~20 | 否（`pdm` 别名保留则通过） |
| 现行文档（README、doc 顶层、skill） | ~8 | ~370 | 迁移目标 |
| 历史快照 `doc/feat/*.md` | ~40 | 大量 | **不改** |

**关键事实**：真正决定命令名的只有 `pyproject.toml` 的 `[project.scripts]`
一行；内核 `pdev/` 无任何逻辑依赖命令名。故改名**不碰内核**。

## 3. 分步路线（推荐顺序）

### 阶段 A：验证 Ledger 接入（当前优先）

- 目标：确认 `pdev/api.py` 的 `Ledger` / `LedgerV2` 子门面接入正确、可回退。
- 依据：`doc/feat/oop-refactor.md`、`doc/feat/ledger-complete.md`。
- 产出：验证通过的结论（笔记 + 验证脚本），供后续合入 `Ledger` 的决策。
- 状态：**待做**。

### 阶段 B：合并主分支 + 推远端

- 当前分支 `feat/web-ui`，本地 `master`，**无 remote**。
- 步骤：
  1. 建 GitHub 仓库（名可用 `dev-ledger`；**不要**用 `pdm` 以免与官方混淆）。
  2. `git remote add origin <url>`。
  3. 将 `feat/web-ui` 合入 `master`（先确认阶段 A 通过）。
  4. `git push -u origin master`，让其余设备可 `clone` 阅读、修改。
- 目的：跨设备协作与阅读，非发布。**此时命令名保持 `pdm` 不影响任何东西。**
- 状态：**待做**。

### 阶段 C：加命令别名 `dl`（兼容期，最小改动）

只改 `pyproject.toml`：

```toml
[project.scripts]
pdm = "pdev.cli:entry"   # 旧名保留，兼容一切现有脚本/文档
dl  = "pdev.cli:entry"   # 新增，个人与后续文档使用
```

- 内核、测试、`.pdm/` 数据**全部不动**。
- 副作用：文档里的 `pdm xxx` 仍有效（因别名还在）。
- 状态：**待做**。

### 阶段 D：迁移"现行入口"文档到 `dl`

只改这些文件里的 `pdm ` → `dl `：

| 文件 | 说明 |
|------|------|
| `README.md` | 命令一览、快速开始 |
| `doc/使用方法以及效果.md` | 全流程用法 |
| `doc/配置文件说明.md` | 环境变量前缀等（`PDM_*` 需一并评估） |
| `doc/TUI使用说明.md` | 界面入口命令 |
| `.pi/skills/pdm-workflow/SKILL.md` 与 `references/*` | AI 代理技能 |
| `.pi/skills/pdm-workflow/scripts/pdm` | 包装脚本（可改名 `dl`） |
| `run.sh` | 本地入口 |

**不改**：`doc/feat/*.md`（历史快照）、`doc/DESIGN_OBSERVATIONS.md`
（历史观察记录，含引用原话）。

- 状态：**待做**。

### 阶段 E：发布到 PyPI

- 仅当阶段 A~D 完成且验证通过后进行。
- `pyproject.toml` 改 `name = "dev-ledger"`；确认 `[project.scripts]` 以
  `dl` 为主。
- 发布步骤：`python -m build` → `twine upload dist/*`。
- 用户安装后：`pip install dev-ledger`，命令 `dl`。
- 状态：**待做（最后）**。

## 4. 风险与注意

| 风险 | 说明 | 应对 |
|------|------|------|
| 命令名撞车 | 若发布后仍注册 `pdm`，用户装官方 PDM 会互相覆盖 | 发布版**不注册** `pdm`，或保留为可选兼容 |
| 文档漂移 | 部分文档改 `dl`、部分留 `pdm`，出现不一致 | 只改"现行入口"，明确保留历史快照；README 顶部标注 `dl` 为主、`pdm` 为兼容别名 |
| 环境变量前缀 | 现为 `PDM_*`，文档与代码均引用 | 迁移时评估是否同步改 `DL_*`（改动面大于命令名，可延后） |
| 数据目录 `.pdm/` | 存储路径含 `pdm` 字样 | **不改**（改则需数据迁移，且 `.gitignore` 已忽略，不入库） |
| 目录名拼写 | 仓库目录 `ProjectDevelopManger`（少一个 a） | 与包名无关，可不动；如需修正另议 |
